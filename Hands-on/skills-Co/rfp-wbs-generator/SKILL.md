# 목적과 입력

Copilot Studio GHCP 하네스에서 **Draft WBS는 구조화된 중간 계획 데이터로, 상세 WBS는 실제 Excel `.xlsx` 파일로 제공**한다. Draft 단계에서는 별도 Excel 파일을 생성하지 않으며, 상세 단계에서는 사용자가 확장자를 지정하지 않아도 파일 생성이 필수다. 요구사항·인력의 신규 분석과 제안서 작성은 이 Skill의 범위가 아니다.

필수 입력은 최신 분석 결과와 HANDOFF의 요구사항·범위·청사진·인력 추천표다. 기존 WBS·공식 일정·공수 기준·제안서 결정 사항이 있으면 함께 사용한다. 입력은 대화나 실제 도구로 읽은 내용이어야 한다. 파일명만으로 확보했다고 간주하지 않는다.

# 수행

1. 모드는 `Draft`(기본) 또는 `상세`로 구분한다. `Final` 요청은 상세 초안으로 처리하며 확정 배정을 의미하지 않는다. Draft는 주요 작업 묶음·단계 중심, 상세는 관리 가능한 Task·Dependency·공수 중심이다.
2. 분석 결과·청사진·인력 추천표의 확보 여부를 확인하고 누락된 입력과 영향을 에이전트에 반환한다. 다른 Skill을 직접 선택·실행하지 않는다. 입력이 부족하면 가능한 작업 구조는 중간 결과로 제시하되 선행 분석 완료로 가장하지 않는다. 제안서는 WBS 작성의 필수 입력이 아니며 기존 제안 결정이 있을 때 반영한다.
3. 분석의 구축·제외·Option 범위를 유지하며 `단계 → Work Package → Task`로 분해한다. 기존 WBS ID를 유지하고 신규 작업에만 ID를 부여한다.
4. 청사진 구성요소·연계별 구현, 보안·운영 설정, 통합·검증 작업을 연결한다. 필요한 보완 제안은 별도 표시하며 새 서비스·SKU를 임의 선정하지 않는다.
5. 추천 인력을 `역할(실명)`으로 담당자 칸에 반영하고 원문 Level·가용성을 함께 유지한다. 미확인·투입 중이면 추천 배치안임을 밝힌다. 이름을 역할명만으로 바꾸거나 후보를 임의 교체하지 않는다. 후보가 없으면 앞 단계의 미확정 상태를 유지한다.
6. RFP 일정·Milestone·고객 검토·외부 의존성을 반영하고 병렬 작업과 선행 작업을 구분한다. 기존 제안서가 있으면 확정된 제안 방향과 대조하고 충돌·영향을 기록한다.
7. Draft는 아래 기본 표와 HANDOFF로 계획 데이터를 검증·전달하고 마친다. 상세는 아래 파일 생성 절차로 `.xlsx`를 생성·검증해 첨부 또는 접근 가능한 다운로드 링크로 제공한다. 기존 HANDOFF에 모드·WBS 데이터·버전·검증 결과를 누적하고, 상세 단계에서만 생성 파일 위치를 추가한다.

# Draft와 상세가 공유할 기본 표

| WBS ID | 단계·작업 | 요구사항 ID / 청사진 ID | 담당 역할(실명)·Level | 가용성 | 일정·기간 | 선행 WBS ID | 산출물·완료 기준 | 공수·근거·상태 |
|---|---|---|---|---|---|---|---|---|

고객 수행 작업, 외부 의존성, Milestone과 Option을 식별한다. 넓은 표는 ID로 연결한 작업표·인력표·일정표로 나눌 수 있지만 연결 값은 유지한다.

# 일정·공수

- 확정 날짜와 RFP 기간을 우선한다. 기준일이 없으면 상대 주차·작업 순서를 사용한다. 기간 근거가 없으면 `[기간 산정 필요]`로 표시한다.
- Task 공수는 사내 표준, 유사 사례, 담당자 제공 값 또는 Task별 산정식이 있을 때 작성한다. `[가정] 값 / 출처·산식 / 변경 영향`을 남긴다. 근거가 없으면 `[인력 산정 필요]`로 둔다.
- 인일·인월·달력 기간·인원은 구분한다. `총 인일 = Task 인일 합계`, `평균 FTE = 총 인일 / 해당 기간 근무일 수`이며 근무일·인월 환산 기준을 명시한다. 기간이 없으면 FTE를 산출하지 않는다.
- 일정과 개인별 투입률이 있으면 중복 배치·최대 동시 투입을 확인한다. 공수만으로 최대 인원을 추정하거나 같은 사람의 병행 작업을 별도 인원으로 중복 계산하지 않는다.

# 모드별 산출물

## Draft — 구조화된 중간 계획 데이터

주요 작업 묶음·단계, 요구사항/청사진 연결 ID, 추천 역할(실명)·Level·가용성, 기간·Milestone·주요 선후행, 가정·미확정을 위 기본 표와 HANDOFF로 정리한다. Task 세분화와 공수는 확보된 근거 범위에서만 작성한다.

대화에 계획 표를 제시하고 후속 제안서가 바로 읽을 수 있도록 필요한 데이터를 HANDOFF에 포함하거나 실제 조회 가능한 결과에 연결한다. **별도 `.xlsx` 생성·템플릿 확보·복사·서식 검증 절차는 수행하지 않는다.** 내용 검증과 인계가 끝나면 `Draft WBS 정리 완료`로 보고한다. Excel 파일이 없다는 이유로 Draft를 미완료로 처리하지 않는다.

## 상세 — Excel(.xlsx)

아래 템플릿 확보·파일 생성·서식 검증 절차는 상세 모드에만 적용한다.

산출물은 `{고객사 또는 프로젝트명}_WBS_상세_{YYYYMMDD}.xlsx`다. 사용자 지정 파일명이 있으면 우선하며 확장자는 `.xlsx`로 유지한다. 대화에는 파일 첨부/다운로드 링크, 주요 내용, 가정·미확정 사항과 검증 결과를 요약한다. 텍스트 표나 CSV의 확장자만 바꾼 파일로 완료 처리하지 않는다.

1. 아래 지식 템플릿 확보 절차로 **표준 WBS 원본 바이너리**를 확보하고, 현재 하네스에서 실제 사용할 수 있는 파일 생성·저장·첨부 도구를 확인한다.
2. 원본을 복사해 값·필요 수식만 채우고 시트·열·헤더·병합·서식·간트 구조를 보존한다. 상세 작업 데이터를 원본에 채워 `.xlsx`로 저장한다. 참고 WBS는 내용만 읽으며 고객명·일정·공수·서식을 복사하지 않는다.
3. 저장 후 재열기, Template 구조·서식 비교, 수식 참조와 Task 일정·간트 일치를 검증한다. 청사진 연결 ID, 추천 실명·Level·가용성이 파일에 유지되는지 확인한다. 일정 미확정은 간트 검증의 미확정 사유로 기록하고 임의 날짜로 채우지 않는다.
4. 파일 존재·크기·Excel 형식과 첨부/링크 접근 가능 여부를 확인한다. **실제 파일 생성 + 필수 검증 통과 + 파일 제공**까지 완료해야 상세 WBS 산출물 완료다.

도구나 원본이 없으면 확보 가능한 경로를 확인한 뒤 부족한 도구·파일과 해결 방법을 보고하고 `상세 WBS .xlsx 생성 미완료`로 표시한다. 작성 가능한 표는 중간 결과로 제공할 수 있지만 최종 산출물을 대신하지 않는다. 내부 저장 경로만 표시하고 다운로드 파일을 제공했다고 주장하지 않는다.

## 지식 이름·설명으로 템플릿 식별·확보

- 연결된 **지식(Knowledge)의 이름과 설명**에서 `WBS 작성용 표준 템플릿·양식`으로 안내된 지식을 선택한다. 특정 지식 이름이나 실제 파일명을 고정하지 않는다. 사용자가 지식 항목을 지정하면 해당 항목을 우선 확인한다.
- 지식 목록·설명 또는 검색 도구에서 `WBS`, `템플릿`, `표준 양식`, `Template` 등 용도 중심으로 탐색한다. 지식 이름의 문자열 일치만 요구하지 않고 설명에 명시된 사용 목적까지 읽는다. 파일명·확장자를 검색 필수 조건으로 삼지 않는다. 로컬 assets·첨부보다 지식 탐색을 우선하고, 이미 확보한 동일 지식·버전의 원본은 재사용한다.
- 지식 설명에서 **산출물 생성에 사용할 서식 원본인지, 내용 참고용 자료인지** 구분한다. 실적·예시·참고 자료를 표준 템플릿으로 임의 대체하지 않는다. 여러 후보가 있으면 설명의 적용 대상·표준 여부·유효 버전으로 선택하고, 근거가 부족하면 지식 이름·설명과 차이를 제시해 선택을 요청한다.
- 선택 지식의 ID·링크 또는 연결된 원본 식별자를 이용해 파일 조회·다운로드 도구로 **원본 `.xlsx` 바이너리**를 확보한다. 실제 파일명은 조회 결과를 그대로 사용하며 추측하지 않는다. 지식 이름·설명은 선택 기준이고, 원본 파일은 서식 보존을 위한 생성 입력이다. 검색 요약·텍스트 추출·인용 링크만으로 원본을 확보했다고 간주하지 않는다.
- Skill이 직접 지식을 탐색할 수 없으면 에이전트에 `WBS 작성용 표준 템플릿으로 설명된 지식`의 탐색·원본 확보를 요청한다. 에이전트는 지식 이름·설명·식별자와 원본을 Skill 입력으로 전달한다. 실제 도구명은 하네스에 연결된 것을 사용한다.
- 지식은 식별했으나 원본을 가져오지 못하면 지식 이름·ID와 실패 사유를 보고하고 원본 가져오기 도구 연결 또는 해당 지식의 원본 제공을 안내한다. 적합 지식이 없으면 이름·설명에 용도를 명시한 템플릿 지식 등록을 안내한다. 첨부 원본은 지식에서 확보하지 못한 경우의 보완 경로로 사용한다. 같은 검색을 반복하거나 텍스트로 양식을 재현하지 않는다.
- HANDOFF에 **지식 이름·설명(용도)·ID/링크·버전/수정일·선택 근거·원본 확보 상태**를 기록한다. 실제 원본 파일명·파일 식별자는 확보한 경우 함께 기록한다.

선택한 표준 원본은 상세 WBS 파일 생성에 사용한다. Draft는 템플릿 없이 계획 데이터를 정리한다.

# 인계와 완료 검증

`HANDOFF`에 모드(Draft/상세)·프로젝트·버전·선행 결과의 위치/버전, 새로 작성한 WBS ID·연결 ID·단계·담당자·일정·Dependency·산출물·공수 근거·미확정을 포함한다. 제안서가 없으면 제안 결정은 `미작성`이다. 선행 요구사항·범위·청사진·실명 인력의 값은 유지한다. 선행 결과를 실제로 조회할 수 있으면 해당 자료와 신규·변경 정보를 연결하고, 조회할 수 없으면 다음 작업에 필요한 값을 직접 포함한다. 파일명이나 “앞 단계 참조”만으로 인계를 대신하지 않는다.

요구사항·청사진 주요 구성요소의 구현·검증 작업 누락, 제외 범위의 작업 혼입, 선후행 모순·순환, RFP 일정 위반, 실명·Level·가용성 소실을 확인한다. 일정·공수는 확인된 값과 가정을 구분한다. Draft는 계획 내용 검증과 인계가 완료된 경우에, 상세는 실제 파일 생성·검증·제공까지 성공한 경우에만 해당 모드의 완료로 보고한다.
