# 목적과 입력

Copilot Studio GHCP 하네스에서 검토 가능한 한글 RFP 분석 초안을 만든다. 상세 작업·공수 산정과 제안서 작성은 이 Skill의 범위가 아니다.

입력은 RFP·첨부·공식 정정/Q&A, 기존 분석·HANDOFF, 고객 환경, 지식 검색으로 확보한 인력 자료와 기술 자료다. 현재 대화 또는 실제 도구로 읽은 자료만 사용한다. 로컬 경로나 다른 Skill의 파일에 자동 접근한다고 가정하지 않는다.

# 수행

1. 기존 분석의 프로젝트·버전·출처를 확인하고 유효한 결과를 재사용한다. 새 RFP·정정 내용은 변경분과 영향을 기록한다.
2. 사업 목적·기간·제약을 요약하고 요구사항에 원문 ID를 유지한다. ID가 없으면 `REQ-001`부터 부여한다. 요구사항별 출처, 대응 방향, 구축·제외·Option 범위를 연결한다.
3. 아래 청사진과 인력 추천을 필수로 수행한다. 지식 검색 도구가 있으면 인력관리표·인력정보·보유 기술·Level·프로젝트 경험·가용성을 검색한다. 실습의 `기술본부인력관리표.xlsx`가 접근 가능하면 확인한다. 검색 요약에 업무 역량 필드가 부족하면 원문·관련 행을 추가 조회한다. 에이전트가 이미 조회한 원문/관련 행이 입력에 있으면 재검색 없이 재사용한다.
4. 상위 수행 단계, 고객 수행 사항, 외부 의존성, 범위·기술·일정·운영 리스크를 정리한다. 고객 질의는 관련 ID, 질문, 미확인 시 영향과 우선순위를 포함한다.
5. 분석 결과와 아래 HANDOFF를 반환한다. 이 단계에서 상세 Task 공수·가격·확정 인원을 만들지 않는다.

# 구축 청사진 — 반드시 포함

요구사항을 실제 서비스 구성과 연결하고 구성요소 ID `BP-001` 등을 부여한다.

| 구성요소 ID | 요구사항 ID | 서비스·제품 / 역할 | SKU·사양·수량·사용량·기간 기준 | 연계 대상·방향 | 보안·운영 | 선정 근거·출처·상태 |
|---|---|---|---|---|---|---|

- 사용자/앱, API·외부 연계, 데이터, 인증·권한, 네트워크, Secret 관리, 모니터링, 백업·복구 중 사업에 필요한 구성을 식별한다. Azure 사업은 Azure Service·Resource와 SKU/Tier 후보를 명시한다. RFP가 지정한 다른 기술은 우선 반영한다.
- RFP에 명시된 사양·수량·기간은 그대로 적용한다. 누락 값은 공식 기술 자료·조회 결과·사내 유사 사례·RFP 계산에 근거한 Baseline과 `[설계 가정]`을 제시한다. 가정은 `[설계 가정] 값 / 출처·계산식 / 변경 영향`으로 표시한다. 출처 없는 관행값은 사용하지 않는다. 근거를 확보하지 못한 개별 값만 `[사양/수량/사용량 확인 필요]`로 남기고 필요한 입력을 적는다. 서비스 구성 전체를 빈칸으로 대체하지 않는다.
- 직접 요구사항에는 없어도 구축 완결에 필요한 보안·운영 구성은 이유와 함께 `[아키텍처 보완 제안]`으로 구분한다. 계약 범위에 자동 포함된 것으로 단정하지 않는다.
- 핵심 흐름을 `입력 → 인증·검증 → 처리·연계 → 저장 → 결과·실패 처리`로 설명한다. 다이어그램이 필요하면 표와 같은 구성요소 ID·서비스를 사용한다. 가격은 산정하지 않는다.

# 실제 인력 추천 — 지식 자료가 있으면 반드시 수행

범위·기술·책임에서 역할과 필요 Level을 도출하고 **지식에 존재하는 실명 후보**와 매칭한다. 기술·직무 적합성 → 사내 Level → 유사 경험·자격 → 가용성을 비교한다. Level은 인력 자료의 원문 체계를 사용하며, 체계를 모르면 `[Level 기준 확인 필요]`로 표시한다.

| 역할·주 투입 단계 | 필요 Level·산정 근거 | 1순위 실명·원문 Level | 대체 후보 | 추천 근거·출처(자료/시트/행 등) | 가용성·데이터 기준일 | WBS 담당자 표기 | 제안서 표기 |
|---|---|---|---|---|---|---|---|

- 확인된 기술·경력·자격만 추천 근거로 사용한다. 관련 필드가 없으면 이름만 보고 적합성을 추정하지 말고 해당 근거를 추가 조회한다. 대체 후보가 없으면 `적합 대체 후보 없음`으로 적는다.
- 가용성은 `확정`(명시적 배정 가능 확인), `확인 중`(자료 없음), `투입 중`(다른 프로젝트 배정 확인), `외부 확보 필요`로 구분한다. 미확인·투입 중이어도 역량이 맞으면 추천하고 상태·조정 필요를 병기한다. 과거 데이터는 기준일과 재확인 필요를 표시한다.
- WBS 표기는 `역할(실명)`, 제안서 표기는 `실명(원문 Level, 추천 후보 · 가용성 상태)`로 전달한다. 추천을 확정 배정으로 바꾸지 않는다.
- Level이 부족하면 `[Level Gap]`과 상위 리뷰 등 보완 방안을 제시한다. 적합 후보가 없으면 `[적합 인력 없음/추가 확보 필요]`로 표시한다.
- 자료가 없거나 읽지 못하면 조회 경로·누락을 밝히고 역할은 작성하되 실명은 `[추천 인력 확인 필요]`로 남긴다. 인물을 만들어내지 않는다. 업무와 무관한 개인정보는 출력하지 않는다.

# 출력과 인계

사업 요약 / 요구사항·범위 / 구축 청사진·흐름 / 실명 인력 추천표 / 수행 단계·리스크·고객 질의를 간결한 표 중심으로 작성한다. 끝에 다음 값을 담은 `HANDOFF`를 붙인다. 분석 본문의 표가 실제로 읽을 수 있는 파일·자료로 제공되면 위치·버전과 해당 표를 연결하고, 연결 자료를 읽을 수 없으면 필요한 값을 인계 블록에 직접 포함한다.

- 프로젝트·분석 버전·작성 기준일·출처 및 데이터 기준일
- 요구사항 ID·내용·출처·상태, 구축·제외·Option·고객 범위
- 청사진 표·인력 추천표의 값 또는 실제 조회 가능한 해당 표의 위치·버전, 상위 수행 단계·일정 제약
- 미확정·충돌·가정과 변경 영향, WBS·제안서에 반영할 사항
- WBS와 제안 결정은 기존 결과가 없으면 `미작성`

# 완료 검증과 한계

주요 요구사항이 청사진에 연결되는지, 서비스별 기준 구성과 가정 근거가 있는지 확인한다. 인력 자료를 확보했으면 적합 실명 후보·원문 Level·추천 근거·가용성이 출력과 HANDOFF 모두에 있는지 확인한다. 자료가 없거나 후보가 부적합하면 사유를 남긴다. 확인되지 않은 계약 조건·실적·인증·가용성을 생성하지 않는다. 일부 자료 부족으로 가능한 분석까지 중단하지 않는다.
